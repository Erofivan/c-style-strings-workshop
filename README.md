# C-style strings workshop

Семинар для новичков: пишем свою версию `<cstring>` руками — от `my_strlen` до `my_strtok`.
Никакого `std::string`, только массивы символов, указатели и нуль-терминатор `'\0'`.

Работаем по циклу: реализовал функцию → прогнал её тест → перешёл к следующей.

---

## Быстрый старт

```bash
# 1. Один раз: сконфигурировать сборку
cmake -S . -B build

# 2. Собрать всё
cmake --build build

# 3. Прогнать ВСЕ тесты
ctest --test-dir build --output-on-failure
```

Сразу после клонирования все 22 теста падают — так и должно быть: функции ещё не написаны.

### Прогнать тест одной функции

```bash
# по имени функции (без префикса my_)
ctest --test-dir build -R "^strlen$" --output-on-failure

# пересобрать и проверить одну функцию
cmake --build build && ctest --test-dir build -R "^strlen$" --output-on-failure
```

Можно запускать и напрямую — вывод тот же, но без обёртки CTest:

```bash
cmake --build build --target test_strlen && ./build/tests/test_strlen
```

### Прогнать один конкретный тест

Аргумент исполняемого файла — фильтр по имени теста (достаточно подстроки):

```bash
./build/tests/test_strlen strlen_stops_at_first_nul   # ровно один тест
./build/tests/test_strlen stops                       # все, где есть "stops"
```

### Полезные команды

```bash
ctest --test-dir build -N                       # список всех тестов
ctest --test-dir build --output-on-failure -j8  # все тесты параллельно
ctest --test-dir build --rerun-failed --output-on-failure  # только упавшие
cmake --build build --target check               # собрать всё и прогнать ctest одной командой
cmake --build build --target playground && ./build/playground  # песочница первой части семинара
```

> `-R` — это регулярное выражение. `-R strlen` найдёт `strlen`, а `^strcpy$` не зацепит соседей.
> Если что-то странное со сборкой — просто удалите папку: `rm -rf build` и сконфигурируйте заново.


## Правила

1. Нельзя использовать `std::string`, `std::vector`, `std::string_view` и функции из `<cstring>`.
2. Можно: указатели, индексы, циклы, 
3. `new[]`/`delete[]` (только в `my_strdup`).
4. Все функции полагаются на `'\0'` — строка кончается там, где стоит нулевой байт.
5. За размер буфера `dest` отвечает вызывающий код. Наши функции его не проверяют — ровно как в настоящем C.
6. Реализованные функции можно (и нужно) переиспользовать: `my_strcat` естественно пишется через `my_strlen` и `my_strcpy`.

## Задачи

### Блок 1. Длина и сравнение

#### 1. `std::size_t my_strlen(const char* str)` — тест `strlen`

Количество символов до `'\0'`, сам `'\0'` не считается.

* `my_strlen("")` → `0`
* `my_strlen("abc")` → `3`
* строка обрывается на первом `'\0'`, даже если массив длиннее.

#### 2. `int my_strcmp(const char* lhs, const char* rhs)` — тест `strcmp`

Лексикографическое сравнение. Возвращает отрицательное число, если `lhs < rhs`, `0` при равенстве, положительное, если `lhs > rhs`.

* Конкретное значение не важно — важен знак.
* Сравнивать символы нужно как `unsigned char` (иначе байт `200` окажется «меньше» буквы `'a'`).
* Префикс меньше целого: `"abc" < "abcd"`.

#### 3. `int my_strncmp(const char* lhs, const char* rhs, std::size_t count)` — тест `strncmp`

То же, но сравниваем не больше `count` символов.

* `count == 0` → всегда `0`.
* Если встретили `'\0'` в обеих строках — сравнение закончено, дальше читать нельзя.

### Блок 2. Копирование и склейка

#### 4. `char* my_strcpy(char* dest, const char* src)` — тест `strcpy`

Копирует `src` в `dest` вместе с `'\0'`. Возвращает `dest`.

* Байты за концом строки в `dest` не трогаем.

#### 5. `char* my_strncpy(char* dest, const char* src, std::size_t count)` — тест `strncpy`

Копирует ровно `count` символов. Возвращает `dest`.

* Если `src` короче `count` — остаток добивается нулями.
* Если `src` длиной `≥ count` — `'\0'` не дописывается (классическая ловушка настоящего `strncpy`).
* Ровно `count` байт — ни байтом больше.

#### 6. `char* my_strcat(char* dest, const char* src)` — тест `strcat`

Дописывает `src` в конец `dest`. Возвращает `dest`.

* Писать начинаем с позиции `'\0'` строки `dest`, а не с её начала.

#### 7. `char* my_strncat(char* dest, const char* src, std::size_t count)` — тест `strncat`

Дописывает не более `count` символов из `src`. Возвращает `dest`.

* Результат всегда завершается `'\0'` — в отличие от `my_strncpy`.

### Блок 3. Поиск

#### 8. `const char* my_strchr(const char* str, int ch)` — тест `strchr`

Указатель на первое вхождение символа `ch`, иначе `nullptr`.

* `ch` приводится к `char`.
* `'\0'` тоже можно искать — тогда возвращается указатель на конец строки.

#### 9. `const char* my_strrchr(const char* str, int ch)` — тест `strrchr`

То же, но последнее вхождение. Так, например, вырезают имя файла из пути.

#### 10. `const char* my_strstr(const char* haystack, const char* needle)` — тест `strstr`

Указатель на первое вхождение подстроки `needle`, иначе `nullptr`.

* Пустая `needle` → возвращаем `haystack`.
* Наивный алгоритм `O(n·m)` — то, что нужно; после частичного совпадения поиск продолжается со следующей позиции.

#### 11. `std::size_t my_strspn(const char* str, const char* accept)` — тест `strspn`

Длина начального куска `str`, состоящего только из символов набора `accept`.

* `my_strspn("129abc", "0123456789")` → `3`.

#### 12. `std::size_t my_strcspn(const char* str, const char* reject)` — тест `strcspn`

Зеркальная задача: длина начального куска, где нет ни одного символа из `reject`.

* `my_strcspn("key=value", "=:")` → `3`.

#### 13. `const char* my_strpbrk(const char* str, const char* accept)` — тест `strpbrk`

Указатель на первый символ `str`, который встречается в `accept`, иначе `nullptr`.

### Блок 4. Память

#### 14. `void* my_memset(void* dest, int value, std::size_t count)` — тест `memset`

Заполняет `count` байт значением `value`, приведённым к `unsigned char`. Возвращает `dest`.

* Работать нужно через `unsigned char*`: `void*` разыменовать нельзя.

#### 15. `void* my_memcpy(void* dest, const void* src, std::size_t count)` — тест `memcpy`

Копирует ровно `count` байт. Возвращает `dest`.

* Нули внутри буфера копирование не останавливают — в этом всё отличие от `my_strcpy`.
* Области памяти не должны пересекаться.

#### 16. `void* my_memmove(void* dest, const void* src, std::size_t count)` — тест `memmove`

То же, но обязано работать при пересечении областей.

* Если `dest < src` — копируем слева направо, иначе справа налево.

#### 17. `int my_memcmp(const void* lhs, const void* rhs, std::size_t count)` — тест `memcmp`

Побайтовое сравнение `count` байт как `unsigned char`. Знак — как у `my_strcmp`.

### Блок 5. Динамическая память и утилиты

#### 18. `char* my_strdup(const char* str)` — тест `strdup`

Копия строки в памяти, выделенной через `new char[]`. Освобождает вызывающий — `delete[]`.

* Не забыть лишний байт под `'\0'`.

#### 19. `char* my_strrev(char* str)` — тест `strrev`

Разворачивает строку на месте. Возвращает `str`.

* Два указателя навстречу друг другу; `'\0'` остаётся на своём месте.

#### 20. `char* my_strtok(char* str, const char* delims)` — тест `strtok`

Режет строку на токены по любому символу из `delims`.

* Первый вызов — со строкой, последующие — с `nullptr`.
* Состояние между вызовами хранится в `static char* saved`.
* Подряд идущие разделители пропускаются, пустые токены не возвращаются.
* Исходная строка модифицируется: разделитель заменяется на `'\0'`.
* Токены кончились → `nullptr`.

### Блок 6. Числа и строки

#### 21. `int my_atoi(const char* str)` — тест `atoi`

Пропустить пробельные символы (` `, `\t`, `\n`, `\r`) → прочитать необязательный знак `+`/`-` → прочитать цифры.

* Останавливаемся на первом не-цифре: `my_atoi("42abc")` → `42`.
* Цифр не нашлось → `0`.
* Переполнение обрабатывать не нужно.

#### 22. `char* my_itoa(int value, char* buffer)` — тест `itoa`

Записывает десятичную запись `value` в `buffer` и ставит `'\0'`. Возвращает `buffer`.

* `0` → `"0"`, отрицательные — со знаком `-`.
* Цифры получаются в обратном порядке — пригодится `my_strrev`.
* Должно работать и на `INT_MIN` (`-2147483648`): модуль этого числа в `int` не помещается.

## Как читать вывод теста

```
  * strlen_simple
    [FAIL] tests/test_strlen.cpp:11
           my_strlen("abc") -> 0, ожидалось 3
ПРОВАЛЕНО: 4 из 6 тест(ов)
```

`* имя_теста` — какой сценарий выполнялся, `[FAIL]` — файл, строка, что получили и что ждали.
Невидимые символы в выводе экранируются: `"ab\0\0"` — это буфер с нулями внутри.

Макросы фреймворка (`tests/test_framework.h`), если захотите дописать свои тесты:

| Макрос | Что проверяет |
|---|---|
| `CHECK(cond)` | условие истинно |
| `CHECK_EQ(a, b)` | `a == b` |
| `CHECK_STREQ(a, b)` | C-строки совпадают по содержимому |
| `CHECK_BYTES(a, b, n)` | первые `n` байт совпадают (видит `'\0'` внутри) |
| `CHECK_NEGATIVE(e)` / `CHECK_POSITIVE(e)` | знак результата (для `strcmp`) |
| `CHECK_NULL(e)` | указатель равен `nullptr` |
| `REQUIRE_NOT_NULL(e)` | не `nullptr`, иначе тест прерывается |
